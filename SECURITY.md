# Политика безопасности

## Поддерживаемые версии

| Версия | Поддержка |
| ------ | --------- |
| 1.x    | ✅ Поддерживается (ветка `main`) |

Проект находится в активной разработке; обновления безопасности выпускаются для последней версии на ветке `main`.

## Как сообщить об уязвимости

**Пожалуйста, не создавайте публичный Issue для уязвимостей.**

1. Используйте функцию [Private Vulnerability Reporting](https://github.com/burovgena-eng/cargohs54/security/advisories/new) на GitHub, **или**
2. Напишите на почту: `info@cargohs54.ru` с темой «[SECURITY] CargoHS54»

В сообщении укажите: описание уязвимости, шаги воспроизведения, затронутые компоненты и, при возможности, оценку серьёзности (CVSS).

**Сроки ответа:** первичный ответ — в течение 7 дней. Так как это учебный/портфолио-проект, фиксированные SLA не гарантируются, но все сообщения будут рассмотрены.

## Что входит в сферу безопасности

- Аутентификация и управление сессиями (JWT, cookies)
- Авторизация на уровне API-эндпоинтов
- SSRF/XSS/SQL-инъекции/IDOR
- Утечка конфиденциальных данных через публичные эндпоинты
- Безопасность Docker-образа и конфигурации деплоя

## Вне сферы

- Автоматизированное сканирование без демонстрации реальной уязвимости
- Атаки, требующие физического доступа к инфраструктуре
- Сообщения о устаревших версиях библиотек без эксплуатируемого вектора атаки

## Принятые меры безопасности в проекте

- Пароли хешируются bcrypt (10 rounds)
- JWT-секрет обязателен в production (fail-fast при отсутствии)
- Rate limiting на вход и анонимный доступ к image-proxy
- SSRF-защита прокси (блокировка приватных подсетей, whitelist content-type)
- Проверка роли в каждом защищённом API-хендлере
- Security-заголовки (X-Frame-Options, X-Content-Type-Options, Referrer-Policy, HSTS)
- Docker: non-root пользователь, standalone-сборка
